# 验证结果

- Node 内置测试：4 项通过，覆盖原有 JSON 结构、BOM / 尾逗号、密码特殊字符保真、导出再导入、非法格式和网址拒绝、合并去重保留原密码，以及域名、端口、路径和内网 IP 匹配。
- Chromium 页面自动化：新增、编辑、搜索、删除确认与取消、粘贴导入、重复导入、下载 JSON 内容、刷新后恢复、恶意 HTML 按文本展示、存储写入失败保留数据与编辑弹窗、390px 页面无横向溢出均通过。
- 页面自动化使用本地 HTTP 页面和模拟的 `chrome.storage` 接口；生产代码仅调用真实 Chrome API，无浏览器网站存储回退。
- 当前执行环境的 Chromium 管理员策略禁止加载未打包扩展，实际扩展安装、扩展图标打开页面及真实 `chrome.storage.local` 持久化尚未实测。请按 README 在本机 Chrome 加载扩展验证。
- v1.1 填充函数已在 Chromium 普通页面上执行验证：填充用户名密码、触发 input 事件、不提交表单、再次校验域名、排除注册密码框和不可编辑输入框、多密码框歧义拒绝、根据焦点选择目标表单、仅密码表单均通过。
- v1.1 弹出面板用模拟 Chrome API 验证了主机名匹配、账号选择、脚本执行参数、结果反馈和密码不在面板明文显示。真实扩展权限与 executeScript 调用仍需本机 Chrome 安装后验证。
- `node --check` 已检查管理页、弹出面板与填充脚本语法。

- v1.2 Chromium 页面验证（模拟存储）：相同主机名不同协议、端口与路径合组；子域名和 IP 分组；每组数量、域名统计、组内更新时间排序、搜索后的分组与数量、无结果状态、390px 无横向溢出均通过。

- v1.2.1：之前发布的 ZIP 清单均能正常解析为 JSON。新增 macOS 原目录更新脚本；bash 语法和 Linux 模拟更新流程已验证，JXA 与 macOS 系统权限无法在当前 Linux 环境实测。

- v1.3：Chromium 页面（模拟存储）验证了同域名实时提示、同名不同密码（同页和跨页）保存、同页同账号同密码拒绝、跨页相同凭据提示后允许保存、编辑排除自身、子域名隔离和提示不包含密码。导入测试验证不同密码均保留、仅完全重复条目跳过、导出再导入不丢条目。

- 更新脚本修复：启动时自动从 sh / Bash POSIX 模式切换到普通 Bash。Linux 下分别用 /bin/sh、/bin/bash、/bin/bash --posix 完整执行模拟更新，均通过原目录保留、代码备份、损坏清单修复、非法更新包拒绝测试；macOS JXA / ditto 以模拟工具代替，尚未本机实测。
