# 本地账号簿 · Chrome 扩展

无需构建、无需服务器，支持 Chrome / Edge 的 Manifest V3 扩展。

## 安装

1. 解压 `local-password-manager.zip`，保留解压后的文件夹。
2. 在 Chrome 地址栏打开 `chrome://extensions`（Edge 为 `edge://extensions`）。
3. 打开右上角“开发者模式”，点击“加载已解压的扩展程序”。
4. 选择包含 `manifest.json` 的 `local-password-manager` 文件夹。
5. 在扩展菜单中固定“本地账号簿”，点击图标打开账号填充面板；点击面板右上角“管理账号”打开管理页面。

## 在登录页填充

1. 在管理页保存账号，网站地址填写实际登录页面的完整 URL。
2. 打开网站，点击账号或登录密码框，旁边会出现“填充账密”。当前页面只匹配到一个账号时点击即填入；多个账号则展开选择，不自动提交。旁边的下拉箭头始终可以打开选择列表或域名查找。
3. 默认只显示当前页面账号；找不到时点击“在当前域名下查找”，可搜索名称、用户名和 URL，再选择其他页面的账号。之后可在管理页编辑该账号的 URL。
4. 浏览器工具栏的扩展图标也支持当前页面优先、手动切换域名查找。

页面匹配比较协议、主机名、端口和路径，忽略查询参数和普通锚点；`#/login`、`#!/login` 这类前端路由也会区分。路径大小写及末尾斜杠保持精确区分。例如 `/app-a/login` 默认不会显示 `/app-b/login` 或另一端口的账号。域名查找可跨路径、端口和协议，但仅限完全相同的主机名；子域名和相似域名不会混入。

为了在输入框聚焦时出现入口，1.4.0 新增 HTTP / HTTPS 网站访问权限，需在 Chrome 中允许扩展访问目标网站。扩展不自动填写，不自动提交；选择列表不展示密码，点击后只将选中的凭据填入表单。升级后重新加载扩展，并刷新已打开的网站，让快捷入口生效。

支持普通网页的可见登录输入框，兼容输入事件驱动的常见前端表单；不填充 `new-password` 注册密码框。多个登录表单时先聚焦目标表单。iframe、Shadow DOM、自定义非 input 控件和浏览器受限页面暂不支持。

## 原目录升级（macOS）

每个升级包都包含完整代码，可以跳过中间版本，直接升级最新版本。请优先使用包含 `更新Mac.command` 的升级包，不要卸载原扩展。

1. 如果旧版还能打开，先导出账号 JSON。
2. 将升级包解压到与原安装目录不同的位置，保留 `更新Mac.command` 和旁边的新版 `local-password-manager` 文件夹。从 Git 仓库下载时，也可直接运行项目目录内的 `更新Mac.command`。
3. 双击 `更新Mac.command`，选择 Chrome 原来加载的 `local-password-manager` 文件夹。支持 `sh 更新Mac.command`，会自动切换至 Bash。若系统限制脚本打开，可在终端输入 `bash `（末尾有空格），把该 `.command` 文件拖入终端后回车运行。
4. 脚本先校验新版、备份原代码，再逐个复制文件，最后写入并校验清单，保留原安装目录。
5. 在 Chrome 原扩展条目上点击“重新加载”，或在加载错误弹窗中点击“重试”。新增权限按 Chrome 提示处理。

脚本备份仅为代码备份，不是账号备份。账号仍在 Chrome 的扩展存储中；脚本不会读写浏览器配置文件。不更换扩展 ID，不修改账号结构，不添加 manifest key。

如果显示 `Manifest is not valid JSON. Can't read file.`：检查原目录根层直接有 `manifest.json`，而不是又嵌套了一个 `local-password-manager`；确认文件已完整解压且不是未下载的云端占位文件。清单有效但依然不可读时，检查 macOS“系统设置 → 隐私与安全性 → 文件与文件夹”中 Chrome 对安装目录所在位置（例如“文稿”）的访问权限，如有对应开关请启用后重试。更换整个目录也可能影响已有目录访问授权，需在本机确认。

Chrome 开发者模式的未打包扩展需要手动更新文件并重新加载，本升级包不提供商店自动更新。如果你已经卸载原扩展，卸载时清除的账号数据无法通过代码更新恢复，需要重新导入之前的 JSON。

## 功能

- 账号列表按域名分组，默认全部收起，点击域名或使用键盘可展开、收起；显示每组账号数量。同一管理页内搜索和数据更新保留展开状态，刷新后恢复全部收起；域名按名称排序，组内最近更新优先。网站统计按域名去重，搜索后仍按域名分组。
- 同一主机名下不同路径、端口及 HTTP / HTTPS 归为一组，子域名分开。
- 支持“复制账号”：预填名称、账号、密码、备注和 URL，提示手动修改域名或页面 URL；保存后创建独立记录，取消不新增，原账号不变。
- 新增、编辑、删除账号；按名称、用户名、完整网址及备注搜索。
- 默认隐藏密码，可临时显示 15 秒，或直接复制用户名和密码。
- JSON 文件和粘贴导入；支持 UTF-8 BOM 和末尾多余逗号。
- 导入前检查全部条目并显示导入数量，格式错误时不会写入部分数据。
- 新增或编辑时提示同域名已有账号，同时比较用户名与密码；同名不同密码允许保存。不同页面使用相同账号密码会提示，但仍允许分别保存。
- 同一完整网址、用户名和密码全部相同才判为重复；新增保存会阻止此类重复，导入则跳过。密码不同会保留为独立条目，不覆盖旧记录。
- 导出所有账号，继续采用原有“网址 → 账号数组”格式，增加可选 `notes` 字段。
- 多个管理标签页实时更新，写入加锁，防止并行修改覆盖其他账号。

## 数据格式

```json
{
  "http://192.168.1.41/page/login_zmkm.html": [
    {
      "name": "桐庐白小明",
      "username": "tlbxm",
      "password": "xxxxxxxxxx",
      "notes": "可选备注",
      "createdAt": "2026-09-14T08:56:29.985Z",
      "updatedAt": "2026-09-14T08:56:29.985Z"
    }
  ]
}
```

`username`、`password` 必须是字符串；导入允许空字符串。名称和备注可省略；缺失或无效时间会用导入时间补充。网址仅接受 HTTP / HTTPS，按浏览器 URL 规则规范化，不合并不同路径。内部自动生成 ID，不导出 ID。未识别的额外字段不会导入。

## 本地存储与备份

数据以**明文**保存到当前浏览器配置文件下的 `chrome.storage.local`，不会使用同步存储或发送到服务器；导出的 JSON 也包含明文密码。这是轻量本地账号簿，未提供主密码或加密保险库。申请 `storage`、`activeTab`、`scripting` 权限及 HTTP / HTTPS 网站访问权限；网站访问用于显示输入框旁的快捷入口，只有手动选择填充时才向当前页面传入所选账号，页面脚本可读取已填入表单的内容。

请在可信设备使用，并定期导出备份。卸载扩展、删除浏览器配置文件或清理扩展数据会删除账号；其他电脑或浏览器配置文件需要手动导入。复制内容会进入系统剪贴板，可能受系统剪贴板历史或同步设置影响。本扩展不自动清空剪贴板。

Chrome 本地扩展存储通常限制为约 10 MB；单次导入也限制为 10 MB。保存失败会提示错误，不会主动删除已有数据。更新代码时保留原文件夹并在扩展管理页点击重新加载；更新前建议先导出备份。
