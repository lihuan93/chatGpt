# 拾序 · 个人工作台

一个围绕个人任务、工作记录、团队周报与项目经历积累的中文工作台。

现在同时提供静态网页版与 **Mac 客户端（Tauri + SQLite）**。客户端构建、数据目录、备份与迁移说明见 [desktop/README.md](desktop/README.md)。网页版运行时无需服务端、外部 API 或依赖安装，在线地址统一维护在仓库根 README。

## 这一版能做什么

- 项目下管理任务：新增、编辑、归类、模块、状态、优先级、截止日期、执行者、标签、链接及“本周关注”；支持跨项目筛选和搜索。
- CSV 同步：识别现有“我的任务”导出表头；按“来源名称 + 任务 ID”新增或更新，预览后确认。支持 UTF-8 BOM 和 GB18030、引号内逗号及换行。
- 工作记录：关联任务、日期、实际进展、交付阶段和结果；可以补充背景、我的职责、方案、难点、技术标签和证据链接。
- 工作积累：标记值得留存的记录，跨周按项目汇总。按日期和项目导出 Markdown，作为简历、述职、面试素材；未填写的信息保留“待补充”。
- 周报：自定义起止日期，核对候选任务后加入；支持临时工作、下周计划、事项编辑、合并、按任务拆分及排序。保存为独立快照。
- 团队表格：事项详情、完成进度、责任人和备注，按章节编号。支持复制富文本表格、下载 HTML / Markdown / CSV、导出带任务依据的 AI 素材。
- 本周完成清单：按已确认的实际完成日期导出 CSV，含任务 ID、项目、标题和工作结果。
- 完整 JSON 备份与恢复；多标签页同步与过期编辑保护。旧版项目自动迁为“旧版任务”下的任务，原 localStorage 内容保留。

## 推荐使用流程

1. 点击“导入任务 CSV”，选择文件、确认来源、核对项目归类建议，再导入。
2. 在“我的任务”调整归类与本周关注；点“记进展”记录实际处理情况。
3. 在“工作记录”中补充处理结果。有长期价值的记录标记为“经历素材”，以后再补齐职责、方案和成果。
4. 在“每周汇报”新建周报，调整日期、汇报人和组别，核对候选任务；没有任务 ID 的工作也可直接写为临时事项。
5. 编辑、合并或拆分事项，确认每项进度；预览并复制表格到语雀，保存文档链接，标记已填写。也可导出周报素材交给 AI 润色。
6. 在“工作积累”按项目和日期导出经历素材；定期导出完整 JSON 备份。

## 导入规则

必需列：`标题`、`任务ID`、`任务状态`、`优先级`。支持原文件的其余列：类型、截止时间、标签、执行者、创建时间、更新时间、业务条线、项目、参与者、创建者。时间格式为 `YYYY-MM-DD HH:mm`，按北京时间理解。

- 状态沿用：待处理、开发中、修复中、已解决、已完成、已取消；不把“已解决”直接当作“已发布”。
- 优先级沿用：非常紧急、紧急、普通、较低。
- 同 ID 更新；同名不同 ID 分别保留。来源名称需保持一致，切换来源会建立另一组任务。
- 文件内重复 ID、未知状态、错误日期等异常行不能导入。源更新时间早于已存版本的行跳过。
- 空白字段不清空原值；文件未包含的任务不删除。个人项目归类、模块、链接、关注标记、工作记录和已整理周报不覆盖。
- 标题、状态、优先级等来源字段会在下次导入时同步，修改前可在预览中取消勾选对应行。
- 首次根据标题等信息给出项目归类建议，由用户确认；建议不能替代实际业务判断。来源的“项目”字段另行保留。
- “导入记录”可查看每次变化、撤销最近一次导入。任务已被修改，或新增任务已关联工作记录 / 周报时，阻止直接撤销。
- 用户原始 CSV 不打包进网站、不作为演示数据提交。首次打开为空工作台；浏览器已有旧版数据时迁移。

## 日期与周报口径

默认北京时间周一至周日，也可改成周一至周五或任意日期范围。来源更新时间仅用于筛选候选；导入观察到的状态变化也需要核对，不能当作精确完成时间。

文件没有实际完成日期，所以不从更新时间或导入时间推断完成日。在任务编辑中确认填写完成日期，才纳入“本周完成清单”；状态改为非“已完成”后清除完成日期。

周报交付阶段独立维护，如待提测、已提测、联调中、已完成、已发布。合并不同进度事项会清空进度，要求重新核对；拆分时保留原文字于备注。周报内容保存为文字快照，修改原任务和记录不会重写历史周报。

## 网页版数据与边界

数据保存在当前浏览器当前网站地址的 localStorage（`shixu-workspace-v2`），没有跨设备同步，也未接入云端数据库。首次迁移读取 `shixu-projects-v1`，不删除旧键。浏览器清理数据会影响本工作台，请保管完整备份。

恢复备份会在确认后替换当前工作台，并先尝试下载当前数据备份。兼容旧版 JSON 项目备份，旧数据迁为任务；不能将第二版备份恢复到旧版页面。

本版不调用 AI、不自动写入语雀。表格复制依赖浏览器剪贴板能力，失败时会选中内容供手动复制；语雀最终粘贴效果需人工核对。HTML 可下载后打开复制，CSV 可在电子表格软件中查看。经历素材导出可排除来源 ID 和证据链接，这不会自动匿名化正文中的业务信息。

## 开发与验证

页面入口：`dist/index.html`。`dist/workspace.js` 为共享数据规则，`dist/app.js` 为界面，`dist/storage.js` 适配网页存储或原生 SQLite，`dist/weekly-report.js` 保留日期工具和旧版周报兼容测试。

运行网页无需安装依赖。普通本地环境可执行 `python3 -m http.server 8000 --directory dist`；托管云环境通过 `sites-preview start <此项目绝对目录>` 使用平台预览。

开发测试需要 Node.js 24+：

```sh
npm ci
npm test
```

测试覆盖 CSV 解析、幂等更新、过期文件、空值保留、撤销、旧版迁移、日期边界、周报快照、导出转义，以及基于 jsdom 的任务 / 记录 / 周报 / 恢复备份交互。jsdom 和 Prettier 只作开发依赖，不进入运行时。浏览器布局、真实剪贴板和语雀粘贴需单独验证。
